# ADHD-friendly output integration

Read when changing the operating model's communication defaults or auditing
their source. The daily rules are in SKILL.md; this file records provenance and
integration choices, not another always-loaded instruction set.

Adapted from [i-have-adhd](https://github.com/ayghri/i-have-adhd), by Ayoub Ghriss,
MIT license, reviewed at commit `ff690b6fbd3383e4fce6a7e50c7b409ca9a6a804` on
2026-09-10. Source: `skills/i-have-adhd/SKILL.md`.

The adaptation retains answer-first writing, small executable steps, useful
state reminders, ranked groups, concrete progress, calm error reports, and
supported time estimates. It preserves complete analysis and required detail.

Changes for this harness:

- Use communication preferences without asserting a diagnosis or neurological
  facts about the reader.
- Complete authorized work rather than asking the operator to execute steps the
  agent can perform. Ask only for information or decisions that are needed.
- Restore state when it helps; avoid a repetitive status ritual on every answer.
- End with a next action only when work needs the reader. Completed work does
  not create a new task for them.
- Keep required progress announcements, full explanations, substantive caveats,
  and detailed delegation briefs. Brevity governs presentation, not work quality.
- Integrate into the shared operating model; no separate plugin, activation
  command, diagnosis label, or session mode is installed.
