# Operator voice

`CONTEXT/voice.md` is the well-known slot for the operator's registers, vocabulary, and writing patterns, and for their deliverable brand kit when they keep one. It links to the shared writing rules and routes to any further files it needs.

Read `CONTEXT/voice.md` from the active harness checkout, including a worktree. Outside a harness checkout, resolve the configured harness root, then `~/OPS`. Check that the file exists, not only its directory: an undeployed home checkout must not hide the file in the reviewed worktree. Then read the files it names.

Use the task's register from that file: chat, professional email, or deliverable. Mirror whichever one the operator is in. For any client deliverable, whatever the format (`.docx`, `.pptx`, `.xlsx`, a PDF, or an HTML page a client opens), load its brand kit when it has one and use `design-method` for the design method.

## Client documents that ask for decisions

A decision cannot come before the reader knows what it refers to. When a document asks its reader to decide something, order it so:

1. Context in one paragraph and a road map of the parts.
2. What was done, or the current state.
3. What was found.
4. The proposal: how it works, the options, the cost.
5. Decisions last, on their own final page, each naming the page that explains it. Never ask about an option before the page that describes it.

A different default section order in the voice file's brand kit governs documents that ask for nothing; the decisions-last rule still holds for ones that do.

Judge the draft against this order before it reaches the operator. Rendering it and checking for collisions is not the test: a draft can pass both and still read badly. Each page has one headline sentence that states the takeaway, one main visual, and a line or two of text. No eyebrow labels, subtitles or stacked card text, and no italic emphasis in body text. Headings only where a reader scans: more than a headline and one section label on a page means cut. The reader has zero context, so say what each system is the first time it appears. Judge length by reading time (about 15 minutes unless the voice file says otherwise), not page count. The cover email is short: the headline result, "it's all in the attached report", what is needed back and on which page, and nothing the report already says.

Degrade when absent: if no voice is configured (a fresh, un-bootstrapped copy), use plain professional prose and say the voice is not yet set.
